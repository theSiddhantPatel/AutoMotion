================================================================================
                    AUTOMOTION - BACKEND TECH & TOOLS GUIDE
================================================================================
This guide explains every tool and library used in the AutoMotion backend in simple,
easy-to-understand terms: what it is, why we use it, and how it works in our project.
================================================================================

--------------------------------------------------------------------------------
1. Node.js & TypeScript
--------------------------------------------------------------------------------
• What is it?
  - Node.js is the runtime environment that lets us run JavaScript on the server.
  - TypeScript is JavaScript with strict type-checking on top.
• Why do we use it?
  - Regular JavaScript allows accidental typos and bugs that only show up when the
    app crashes at runtime. TypeScript catches these bugs while typing in the editor.
• How it works in AutoMotion:
  - All files in `src/` are written in `.ts`.
  - Interfaces and types are defined for Bookings, Mechanics, Customers, and APIs
    so that every function knows exactly what data it receives and returns.

--------------------------------------------------------------------------------
2. Express.js
--------------------------------------------------------------------------------
• What is it?
  - A fast, minimalist web framework for Node.js.
• Why do we use it?
  - Node.js alone requires writing low-level HTTP code. Express simplifies creating
    routes (like GET, POST, PATCH), handling JSON request bodies, and applying middleware.
• How it works in AutoMotion:
  - In `src/index.ts`, Express handles incoming HTTP requests.
  - Routes are organized in `src/routes/` for `/api/dashboard`, `/api/bookings`,
    `/api/mechanics`, `/api/customers`, and `/api/simulation`.

--------------------------------------------------------------------------------
3. PostgreSQL & Neon DB
--------------------------------------------------------------------------------
• What is it?
  - PostgreSQL is a powerful, industry-standard relational database.
  - Neon DB is a cloud-hosted, serverless PostgreSQL service.
• Why do we use it?
  - Vehicle service operations need relational tables (Customers have Bookings,
    Bookings are assigned to Mechanics, Bookings have Services).
  - Neon DB means we don't have to install or manage PostgreSQL locally on our computer;
    it provides a cloud connection string instantly.
• How it works in AutoMotion:
  - The connection string (`DATABASE_URL`) is stored in `.env`.
  - All tables and data live securely in the Neon cloud database.

--------------------------------------------------------------------------------
4. Prisma ORM (@prisma/client & prisma CLI)
--------------------------------------------------------------------------------
• What is it?
  - An Object-Relational Mapper (ORM) for TypeScript/Node.js.
• Why do we use it?
  - Instead of writing raw SQL strings (`SELECT * FROM bookings WHERE ...`), Prisma lets
    us query the database using type-safe TypeScript methods like `prisma.booking.findMany()`.
• How it works in AutoMotion:
  - `prisma/schema.prisma`: The single blueprint file where we defined models (Customer,
    Mechanic, ServiceItem, Booking, BookingLog).
  - `npx prisma db push`: Synchronizes the schema with Neon DB and creates tables.
  - `npx prisma studio`: Opens a visual web dashboard in the browser to view and edit database rows.

--------------------------------------------------------------------------------
5. Zod (Request Validation)
--------------------------------------------------------------------------------
• What is it?
  - A TypeScript-first schema validation library.
• Why do we use it?
  - If a user or frontend sends invalid data (e.g. missing customer ID, negative amount,
    invalid status), Zod automatically rejects it with a clear 400 Bad Request error
    before it can corrupt the database.
• How it works in AutoMotion:
  - In `src/types/index.ts`, schemas like `CreateBookingSchema` and `BookingQuerySchema`
    validate incoming request bodies and query parameters.
  - Handled cleanly by `src/middleware/validator.ts`.

--------------------------------------------------------------------------------
6. Socket.io (WebSockets / Real-Time Updates)
--------------------------------------------------------------------------------
• What is it?
  - A library that enables real-time, bidirectional communication between server and browser.
• Why do we use it?
  - Normal HTTP requires the browser to constantly refresh to see new data. WebSockets
    keep a live connection open so the server can push updates instantly without reloading.
• How it works in AutoMotion:
  - `src/sockets/socketManager.ts` initializes Socket.io on the HTTP server.
  - Whenever a booking changes status (e.g. Pending -> Assigned -> En Route -> Completed),
    the backend emits a `booking:updated` event, and connected dashboards update instantly.

--------------------------------------------------------------------------------
7. Morgan (HTTP Request Logger)
--------------------------------------------------------------------------------
• What is it?
  - An HTTP request logger middleware for Node.js.
• Why do we use it?
  - When you make an API call, Morgan prints clean, colored logs in your terminal
    showing the method, URL, status code, and response time (e.g., `GET /api/bookings 200 - 14ms`).
• How it works in AutoMotion:
  - Activated in `src/index.ts` with `app.use(morgan('dev'))`.

--------------------------------------------------------------------------------
8. Helmet (Security Headers)
--------------------------------------------------------------------------------
• What is it?
  - A security middleware package for Express.
• Why do we use it?
  - It automatically sets various HTTP response headers (like hiding X-Powered-By,
    preventing clickjacking, and XSS protection) to secure the API against common vulnerabilities.
• How it works in AutoMotion:
  - Applied in `src/index.ts` with `app.use(helmet({...}))`.

--------------------------------------------------------------------------------
9. CORS (Cross-Origin Resource Sharing)
--------------------------------------------------------------------------------
• What is it?
  - A package that controls which websites/domains are allowed to make requests to our API.
• Why do we use it?
  - By default, browsers block frontend web apps (running on localhost:3000 or Vercel)
    from calling an API running on a different port/domain (localhost:5000). CORS permits this.
• How it works in AutoMotion:
  - Enabled in `src/index.ts` with `app.use(cors())`.

--------------------------------------------------------------------------------
10. Swagger / OpenAPI (swagger-ui-express)
--------------------------------------------------------------------------------
• What is it?
  - An interactive, visual API documentation website generated from API specifications.
• Why do we use it?
  - Satisfies the assignment documentation requirement and allows evaluators or developers
    to test every API endpoint directly in their browser without installing Postman.
• How it works in AutoMotion:
  - Configured in `src/swagger.ts` and mounted at `http://localhost:5000/api/docs`.

--------------------------------------------------------------------------------
11. Faker.js (@faker-js/faker)
--------------------------------------------------------------------------------
• What is it?
  - A popular library for generating realistic mock data (names, addresses, car models, dates).
• Why do we use it?
  - The assignment requires 500+ bookings, 20+ mechanics, and 50+ customers. Writing this
    manually would take days. Faker generates realistic data in seconds.
• How it works in AutoMotion:
  - Used in `prisma/seed.ts` to populate 600+ realistic bookings with varied dates, amounts,
    and mechanics across a metro map.

--------------------------------------------------------------------------------
12. TSX (TypeScript Execute)
--------------------------------------------------------------------------------
• What is it?
  - A fast CLI tool to run TypeScript files directly without a manual compilation step.
• Why do we use it?
  - Replaces traditional nodemon + ts-node. It provides instant hot-reloading: whenever you
    save a file in `src/`, the server restarts in milliseconds.
• How it works in AutoMotion:
  - Configured in `package.json` under `"dev": "tsx watch src/index.ts"`.

--------------------------------------------------------------------------------
13. Dotenv
--------------------------------------------------------------------------------
• What is it?
  - A module that loads configuration variables from a `.env` file into `process.env`.
• Why do we use it?
  - Sensitive information like database passwords and port numbers should never be hardcoded
    in source code.
• How it works in AutoMotion:
  - Loaded in `src/config/index.ts` to read `PORT`, `DATABASE_URL`, and `CLIENT_URL`.

================================================================================
                    QUICK SUMMARY OF USEFUL COMMANDS
================================================================================
• npm run dev           -> Start backend with hot-reload (http://localhost:5000)
• npx prisma db push    -> Push schema changes to Neon PostgreSQL database
• npm run db:seed       -> Seed 600+ realistic bookings and 25 mechanics
• npx prisma studio     -> Open visual database viewer in browser
• http://localhost:5000/api/docs -> Open interactive Swagger API documentation
================================================================================
